# Python: домашнее задание для кандидатов (12.10.2026)

Сделайте небольшой HTTP-сервис на Python, который принимает показания комнатных датчиков и возвращает последнее показание каждого датчика. Все данные вымышленные; подключаться к оборудованию или внешним сервисам не нужно.

## Инструменты

Можно использовать любой Python-фреймворк, документацию, поиск и AI-инструменты. Укажите, где использовали AI и как проверили результат. На встрече нужно будет объяснить код и внести небольшое изменение.

Код, комментарии, сообщения ошибок и README пишите на английском.

## Данные

Каждый запрос передает одно показание:

```json
{
  "event_id": "event-001",
  "sensor_id": "room-01-temperature",
  "value": 22.4,
  "observed_at": "2026-10-12T10:00:00Z"
}
```

Все четыре поля обязательны. event_id и sensor_id: непустые строки. value: конечное JSON-число, не строка и не boolean. observed_at: корректная дата и время в UTC с суффиксом Z; допустимы доли секунды. Неизвестные поля отклоняйте. Диапазон температуры и будущие даты проверять не требуется.

## API

### POST /readings

Принимает одно показание.

- Новое event_id: сохранить показание, вернуть HTTP 201 и `{"status": "accepted"}`.
- Повтор event_id с теми же sensor_id, value и observed_at: вернуть HTTP 200 и `{"status": "duplicate"}`, состояние не менять.
- Повтор event_id с отличающимися данными: вернуть HTTP 409, состояние не менять.
- Неверные данные: HTTP 422. Ответ должен быть JSON с понятным описанием ошибки; точную структуру выберите сами.

event_id уникален для всего сервиса, не только для одного датчика. При сравнении считать 22 и 22.0 одним значением, а разные записи одного момента времени, например с .000Z и без дробной части, одним моментом. Неверный запрос не должен сохранять даже часть данных.

### GET /sensors/{sensor_id}/latest

Возвращает HTTP 200 и последнее показание датчика в формате из примера выше. Если у датчика нет данных, вернуть HTTP 404 с JSON-ошибкой.

Последнее показание определяется по observed_at, а не по времени получения запроса. Более старое показание сохраняется для проверки повторов, но последнее значение не заменяет. Если observed_at совпадает у разных событий одного датчика, оставьте в latest то, которое сервис принял первым.

Форматирование JSON и количество знаков после запятой в ответах не оцениваются.

## Пример проверки

Для одного датчика последовательно отправляем:

1. event-001: 22.4 в 10:00:00Z. Ответ 201; latest содержит event-001.
2. Точный повтор event-001. Ответ 200 duplicate; latest не меняется.
3. event-002: 21.8 в 09:59:00Z. Ответ 201; latest по-прежнему содержит event-001.
4. event-001 с value 25.0. Ответ 409; latest не меняется.
5. event-003: 23.0 в 10:01:00Z. Ответ 201; latest содержит event-003.

## Объем

Достаточно хранения в памяти одного процесса, потеря данных при перезапуске допустима. Приемку проводим последовательными запросами. База данных, Docker, авторизация, деплой, очереди и интерфейс не нужны.

Добавьте несколько автоматических тестов: нормальный прием и чтение, повтор и конфликт event_id, показание с более старым временем, неверный запрос без изменения состояния. Можно использовать стандартные средства тестирования или любую удобную библиотеку.
